| 用語 | 役割・仕組み |
|---|---|
| RA(登録局) | 証明書発行前に申請者の本人確認・審査を行う |
| CA(認証局) | 公開鍵と本人の対応関係を保証し、証明書に署名して発行する信頼の起点 |
| VA(検証局) | 証明書の有効性(失効状態など)の検証機能を提供する |
| PKI (公開鍵基盤)<br>Public Key Infrastructure | 登録局(RA)による申請者の本人確認、認証局(CA)による電子証明書の発行・管理、検証局(VA)による証明書の検証などを通じて、公開鍵暗号方式を安全に運用するための社会的な仕組みやインフラ全体のこと |
| 電子署名 | 電子データに対して、本人だけが保有する秘密鍵を用いて作成する署名データのこと |
| デジタル証明書<br>(電子証明書) | 電子署名の検証に使用する公開鍵が、確かに本人のものであることを証明する電子データ<br>信頼できる第三者機関である登録局(RA)が申請者の本人確認を行い、その確認に基づいて認証局(CA)が発行する |
| X.509証明書 | <ul><li>公開鍵</li><li>所有者情報</li><li>有効期間</li><li>CAの署名</li></ul>を含む証明書のフォーマット規格 |
| CRL(証明書失効リスト) | CAが失効させた証明書のうち、有効期限内のものについて以下を一覧にして定期的に公開するリスト<ul><li>シリアル番号</li><li>失効日時</li><li>失効理由(任意)</li></ul>CAの署名付き<br>有効期限が切れた証明書は掲載不要になる |
| OCSP | 証明書のシリアル番号を指定し、失効状態をCRLをダウンロードせずリアルタイムに問い合わせるプロトコル<br><b>応答の種類</b><ul><li>good : 有効</li><li>revoked : 失効<br>失効日時と失効理由を返す<br>理由の例 : 鍵の漏洩 keyCompromise</li><li>unknown : 不明</li></ul> |
| 信頼の連鎖(Chain of Trust) | ルートCA→中間CA→エンドエンティティ証明書と署名を順にたどって検証する仕組み |
| ルート証明書 | OSやブラウザに事前組み込みされた自己署名のCA証明書で、信頼の起点となる |
| PFS(前方秘匿性)<br>Perfect Forward Secrecy | <ul><li>長期鍵(サーバの秘密鍵等)が将来漏洩しても、<br>過去に交換したセッション鍵・通信内容が復元されない性質</li><li>セッションごとに一時的な鍵ペア(Ephemeral鍵)を生成し、<br>通信終了後に破棄することで実現する</li><li>同じ鍵ペアを使い回す静的(Static)なDH/ECDHでは実現できない<br>(長期鍵の漏洩により過去の全セッションが復元される)</li></ul> |
| 量子鍵配送(QKD)<br>Quantum Key Distribution | <ul><li>QKDは「鍵を安全に共有する」技術であり、データの暗号化自体は別途AESやワンタイムパッド等で行う</li><li>量子状態は測定すると乱れるため、盗聴があると誤り率が上昇し、検知できる</li><li>古典チャネルの認証が別途必要<br>事前共有鍵やPQC署名等を用いる<br>認証が破られると中間者攻撃を受ける</li><li>専用の量子通信機器が必要で、光ファイバでは通信距離や鍵生成速度に制約がある</li><li>実機の検出器等を狙う実装攻撃(サイドチャネル)が課題</li><li>デコイ状態法は個別のプロトコルではなく、弱いコヒーレント光を使う実システムで光子数分離攻撃(PNS攻撃)を防ぐ技術<br>(BB84等と組み合わせて用いる)</li><li>数学的困難性に基づく耐量子計算機暗号(PQC)とは別系統で、両者を併用する考え方もある</li></ul> |
