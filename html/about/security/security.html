情報セキュリティについて

認証技術

| 名称 | 概要 | 仕組み | 主な用途・備考 | | --- | --- | --- | --- | | パスワード認証
(固定式) | ID(利用者識別子)と
パスワード(秘密の文字列)の組み合わせによる、
最も基本的な知識情報ベースの認証方式 |
  • 登録済みの文字列と
    入力された文字列を照合し、
    一致すれば認証成功とする単純な方式
  • 使い回し・単純な文字列は
    辞書攻撃、リスト型攻撃、
    パスワードスプレー攻撃等に弱い
  • 保存時はソルト付きハッシュ化、
    運用面ではアカウントロックアウト等の
    対策と併用するのが一般的
|
  • 最も普及している認証方式
  • 単体では強度が低いため、
    多要素認証の1要素として
    組み合わせて使われることが多い
| | チャレンジレスポンス認証 | パスワード等の秘密情報を
ネットワーク上に平文で流さずに
認証する方式 |
  • サーバがランダムな「チャレンジ」(乱数)を送付
  • クライアントはチャレンジとパスワードから
    ハッシュ値等を計算し「レスポンス」として返送
  • サーバも同じ計算を行い一致を確認
|
  • リプレイ攻撃対策になる
  • APOP、CHAP等で利用
| | CHAP
(Challenge Handshake
Authentication Protocol) | PPP接続等で使われる
チャレンジレスポンス方式の
代表的プロトコル |
  • 接続中も定期的に再認証を行う
  • PAPと異なりパスワードを平文で送らない
|
  • リモートアクセス認証
    (ダイヤルアップ、VPN等)
| | XMLデジタル署名
(XML Signature) | XML文書に対する
デジタル署名の標準規格
(W3C勧告) |
  • 文書全体だけでなく
    特定の要素(一部分)にも署名可能
  • 署名情報自体もXMLで表現される
|
  • デジタル署名・証跡
  • SOAPメッセージ
  • 電子申請システム等
| | タイムスタンプ
(デジタルタイムスタンプ) | ある時刻にその電子データが
「存在していたこと」
「改ざんされていないこと」を証明 |
  • 時刻認証局(TSA)が
    ハッシュ値と時刻情報を結合し署名
  • 完全性の証明＋存在証明(非改ざん証明)
  • デジタル署名だけでは
    「いつ」署名したかは証明できないため併用される
|
  • デジタル署名・証跡
  • 長期署名(電子契約、電子帳簿保存法対応等)
| | コードサイニング認証
(コード署名) | ソフトウェア(実行ファイル、
ドライバ、アプリ等)の
作成者・非改ざんを証明する署名 |
  • 開発者が秘密鍵で
    プログラムに署名
  • OS/ブラウザが証明書を検証し
    発行元・完全性を確認
|
  • デジタル署名・証跡
  • Windowsドライバ署名
  • モバイルアプリ配布
  • マルウェア対策
| | トランザクション署名 | オンラインバンキング等で
取引内容(振込先・金額等)
そのものに対して行う署名 |
  • ログイン認証だけでなく
    個々の取引ごとに署名/承認を要求
  • MITB(Man-in-the-Browser)攻撃対策
|
  • デジタル署名・証跡
  • インターネットバンキングの
    不正送金対策
| | MAC
(Message Authentication
Code：メッセージ認証符号) | 共通鍵を用いて
メッセージの完全性と
送信元認証を実現する符号の総称 |
  • 送信者は共通鍵とメッセージから
    MAC値を計算し、メッセージに付与して送信
  • 受信者は同じ共通鍵で
    MAC値を再計算し一致すれば
    「改ざんされていない」
    「鍵を知る正当な相手からの送信である」
    ことを確認できる
  • 実現方式によりHMAC(ハッシュ関数を利用)、
    CMAC(ブロック暗号を利用)等に分かれる
  • デジタル署名と異なり共通鍵方式のため、
    第三者への証明(否認防止)はできない
|
  • メッセージの完全性検証
  • 送信元認証(なりすまし対策)
| | HMAC
(Hash-based Message
Authentication Code) | MACの実現方式の一つ。
共通鍵とハッシュ関数を
組み合わせて実装するメッセージ認証符号 |
  • HMAC = H(鍵 XOR opad \|\| H(鍵 XOR ipad \|\| メッセージ))
  • SHA-256等の任意のハッシュ関数と
    組み合わせて
    HMAC-SHA256のように利用
  • ハッシュ関数単体(メッセージダイジェスト)と異なり
    鍵を知らないと正しいMAC値を
    計算できないため改ざん検知を回避できない
|
  • TLS、IPsec
  • API認証(署名付きリクエスト)
| | CMAC
(Cipher-based Message
Authentication Code) | MACの実現方式の一つ。
共通鍵ブロック暗号
(AES等)を利用して
実装するメッセージ認証符号 |
  • ブロック暗号のCBCモード等を応用し、
    最終ブロックの暗号化結果をMAC値とする
  • AESと組み合わせた
    AES-CMAC等が代表例
|
  • 組み込み機器等、
    ハッシュ関数より
    ブロック暗号の実装が既にある環境
| | 生体認証全般
バイオメトリクス認証 | 身体的特徴・行動的特徴を
用いて本人確認を行う認証方式 |
  • 身体的特徴：指紋、虹彩、静脈、顔、声紋等
  • 行動的特徴：署名の筆跡、キーストローク等
  • 紛失・盗難・忘却のリスクが
    パスワードより低い
|
  • 入退室管理
  • スマホのロック解除等
| | 指紋認証 | 指先の紋様(隆線)の
パターンを利用 |
  • 低コストでデバイスに搭載しやすい
  • 汗・乾燥・怪我で精度低下する場合あり
|
  • スマートフォン
  • PC
  • 勤怠管理
| | 虹彩認証 | 目の虹彩(瞳孔の周りの模様)
のパターンを利用 |
  • 経年変化が少なく精度が高い
  • 非接触で認証可能
|
  • 空港の入出国審査
  • 高セキュリティ施設
| | 静脈認証 | 手のひらや指の
静脈パターンを利用 |
  • 体内情報のため偽造が困難
  • 非接触で衛生的
|
  • 銀行ATM等
| | 顔認証 | 顔の輪郭・パーツの
位置関係等を利用 |
  • 非接触・遠隔からも認証可能
  • マスクや経年変化の影響を受けやすい
|
  • スマートフォン
  • 空港
| | 声紋認証 | 声の周波数特性等を利用 |
  • 電話等リモートでも利用可能
|
  • コールセンターの本人確認
| | 3Dセキュア
(3-D Secure) | クレジットカードの
オンライン決済における
本人認証サービス |
  • カード会社が発行する
    パスワード/ワンタイムパスコード等で追加認証
  • 3D = 「Three Domain」
    (加盟店・カード会社・決済網の3領域)に由来
  • 現行版(3DS2.0)は
    リスクベース認証を組み合わせる
|
  • ECサイトでのクレジットカード決済
  • なりすまし・不正利用対策
| | CAPTCHA | 人間とコンピュータ
(ボット)を区別するための
認証技術 |
  • 歪んだ文字の読み取り、
    画像選択等、人間には容易だが
    機械には困難なタスクを課す
  • reCAPTCHA等は
    ユーザ行動解析で判定する方式も存在
|
  • ログインフォーム
  • 会員登録
  • 自動投稿(スパム)防止
| | FIDO
(Fast IDentity Online) | FIDOアライアンスが策定する、
パスワードに依存しない
オンライン認証の標準規格群の総称 |
  • 公開鍵暗号方式を採用し、
    秘密鍵は常に端末内
    (セキュリティチップ等) に保持され
    外部へ送信されない
  • 生体認証やPIN等による
    端末内でのローカル認証をトリガーに、
    その結果をもとにサーバと公開鍵認証を行う
  • 策定時期・用途により
    UAF、U2F、FIDO2の3系統に分かれる
|
  • パスワードレスログイン
  • 多要素認証の要素として利用
| | FIDO UAF
(Universal Authentication
Framework) | ID/パスワードの入力自体を
廃止し、生体認証等のみで
ログインする「パスワードレス認証」の規格 |
  • スマートフォン等に搭載された
    指紋・顔・虹彩認証等をトリガーに、
    端末内の秘密鍵で署名しサーバへ送信
  • パスワード自体を持たない
    (登録・使用しない) 方式
|
  • モバイルアプリのパスワードレスログイン
| | FIDO U2F
(Universal 2nd Factor) | 既存のID/パスワード認証を
補強する「第2要素」として
セキュリティキー等を用いる規格 |
  • ID/パスワードでのログイン後、
    USB/NFC/Bluetooth接続の
    セキュリティキーを第2要素として使用
  • キー内の秘密鍵で
    サーバからのチャレンジに署名し返送
  • 接続先ドメインと鍵が
    紐づくためフィッシング耐性が高い
|
  • Google、GitHub等における
    二要素認証 (セキュリティキー)
| | FIDO2 | UAF/U2Fを統合・発展させた
最新世代の規格。
WebAuthnとCTAPの2仕様から構成される |
  • WebAuthn：
    ブラウザ・OSが提供する
    公開鍵認証のためのWeb標準API
    (別項目参照)
  • CTAP
    (Client to Authenticator Protocol)：
    ブラウザ/PCとセキュリティキー等の
    外部認証器を接続するプロトコル
  • 端末内蔵の生体認証等
    (プラットフォーム認証器) と
    外付けセキュリティキー
    (ローミング認証器) の両方に対応
|
  • パスワードレスログイン
  • パスキーの基盤技術
| | パスキー
(Passkey) | FIDO2/WebAuthnをベースとした
パスワードレス認証の実装 |
  • 生体認証等と組み合わせ
    デバイス間で同期可能な
    公開鍵ペアを利用
|
  • Webサービスへのパスワードレスログイン
| | ワンタイムパスワード
(OTP) | 一度限り使用可能な
使い捨てパスワード |
  • HOTP：カウンタ値をもとに生成
  • TOTP：現在時刻をもとに生成
    (Google Authenticator等)
|
  • 二要素認証
  • 送金時の追加認証
| | セキュリティトークン
(ハードウェアトークン) | ワンタイムパスワードを生成する
専用の物理デバイス。
認証の3要素のうち「所持情報」にあたる |
  • 内蔵の時計やカウンタを用いて、
    一定時間ごと／操作ごとに
    使い捨てパスワードを画面に表示
  • ネットワークに接続しない
    スタンドアロン型が多く、
    通信経路上での盗聴リスクが小さい
  • 近年はスマートフォンアプリによる
    ソフトウェアトークンも普及
|
  • 銀行のワンタイムパスワード生成器
  • 企業VPN用トークン(RSA SecurID等)
| | リスクベース認証 | 通常と異なるアクセス
(IPアドレス、端末、地域等)を
検知した場合のみ
追加認証を要求する方式 |
  • IPアドレス、端末情報
    (デバイスフィンガープリント)、
    アクセス時間帯、地理的位置等から
    リスクスコアを算出
  • 普段の行動パターンと異なる場合のみ
    追加のOTP入力等を要求
  • 低リスク時はユーザの
    手間を増やさず利便性を確保
|
  • オンラインバンキング
  • クラウドサービスへのログイン
| | シングルサインオン
(SSO) | 一度の認証で
複数のサービス・システムを
利用可能にする仕組み。
実現方式によって特徴が異なる |
  • エージェント型：
    各サーバに常駐エージェントを導入し、
    認証情報をSSO基盤と連携して認証を代行
  • リバースプロキシ型：
    SSO用リバースプロキシが
    全リクエストを中継し、
    認証済みセッションを各システムへ付与
  • 代理認証型 (フォーム認証代行) ：
    ユーザに代わってID/PWを
    各システムのログイン画面へ
    自動入力し認証を代行
  • フェデレーション型 (ID連携) ：
    IdP (Identity Provider) が認証を行い、
    SP (Service Provider) へ認証結果を連携。
    SAML、OAuth 2.0、OpenID Connectで実現
  • Kerberos認証も
    組織内SSOの実現方式の一つ
|
  • 企業内システム
  • クラウドサービス連携
| | SAML
(Security Assertion
Markup Language) | IdPとSP間で認証結果・属性情報を
XML形式でやり取りする
フェデレーション型SSOの標準規格 |
  • IdPがユーザを認証し、
    「アサーション」
    (認証結果・属性情報) をXMLで発行
  • SPはアサーションの
    デジタル署名を検証し
    ログインを許可
  • ブラウザのリダイレクトを介して
    アサーションを受け渡す
|
  • 企業向けSaaSへのSSO
  • 学認 (大学・研究機関の認証連携基盤) 等
| | OAuth 2.0 | リソースへのアクセス権限を
第三者アプリに委譲するための
「認可」の標準プロトコル |
  • ユーザが認可サーバで
    ログイン・同意を行うと
    クライアントに「アクセストークン」を発行
  • クライアントはアクセストークンを用いて
    リソースサーバのAPIにアクセス
  • 「誰であるか」を証明する認証プロトコルでは
    なく「何を許可するか」を扱う
    認可プロトコルである点に注意
|
  • SNS等と連携する
    「〇〇で連携」機能
  • 外部API連携
| | PKCE
(Proof Key for Code
Exchange) | OAuth 2.0の「認可コード」を
横取りされて悪用される攻撃を防ぐ
拡張仕様 |
  • クライアントが認可要求時に
    ランダムな検証用文字列
    (code_verifier)とそのハッシュ値
    (code_challenge)を生成
  • 認可サーバはcode_challengeを保持し、
    後続のトークン要求時に
    code_verifierから再計算した値と
    一致するか検証
  • クライアントシークレットを
    安全に保持できないモバイルアプリ/
    SPA(シングルページアプリ)で
    特に必須とされる
|
  • モバイルアプリのOAuth認可
  • 認可コード横取り攻撃対策
| | OpenID Connect
(OIDC) | OAuth 2.0を拡張し
「認証」機能を追加した標準規格。
いわゆる「〇〇でログイン」の実体 |
  • OAuth 2.0のアクセストークンに加え
    「IDトークン」(JWT形式)を発行
  • IDトークンにユーザ識別情報を含み
    クライアント側で
    本人認証結果として利用
|
  • ソーシャルログイン
  • 企業向けクラウドサービスのSSO基盤
| | JWT
(JSON Web Token) | 署名付きの情報(クレーム)を
JSON形式でコンパクトに
やり取りするためのトークン形式 |
  • Header(ヘッダ).Payload(ペイロード).
    Signature(署名)の3要素を
    ピリオドで連結しBase64URLエンコード
  • 署名により改ざん検知が可能
    (内容自体は暗号化されず
    誰でもデコードして閲覧可能な点に注意)
  • 署名方式には共通鍵によるHMAC(HS256等)や
    公開鍵によるRSA/ECDSA(RS256、ES256等)がある
|
  • OpenID ConnectのIDトークン
  • APIの認可情報(アクセストークン)の
    フォーマットとして利用
| | WebAuthn
(Web Authentication API) | パスワードを使わず
公開鍵暗号方式でWebサイトへの
ログインを実現するW3C標準API
(FIDO2の構成要素) |
  • ブラウザ組み込みAPIとして
    認証器 (生体認証、セキュリティキー等) を呼び出す
  • サイト (オリジン) ごとに
    異なる鍵ペアを生成し、
    秘密鍵は認証器内から取り出さない
  • ドメインと鍵が紐づくため
    フィッシング耐性が高い
|
  • パスワードレスログイン
  • パスキーの基盤技術
| | Kerberos認証 | チケットベースの
ネットワーク認証プロトコル |
  • KDC(鍵配布センタ)が
    チケットを発行
  • パスワードをネットワークに
    流さず相互認証を実現
|
  • Windowsドメイン(Active Directory)認証等
| | 多要素認証
(MFA) | 「知識情報」「所持情報」
「生体情報」のうち
2つ以上を組み合わせる認証 |
  • 知識情報：パスワード、PIN
  • 所持情報：ICカード、スマートフォン、
    ワンタイムパスワードトークン
  • 生体情報：指紋、虹彩等
|
  • 重要システムへのログイン
  • 金融取引
|

| 指標 | 名称(正式名) | 意味 | 備考 | | --- | --- | --- | --- | | FRR | False Rejection Rate
(本人拒否率) | 本人なのに
他人と誤って拒否してしまう確率 |
  • 閾値を厳しくするとFRRは上昇(利便性低下)
| | FAR | False Acceptance Rate
(他人受入率) | 他人なのに
本人と誤って受け入れてしまう確率 |
  • 閾値を緩くするとFARは上昇(安全性低下)
| | CER
(EER) | Crossover(Equal) Error Rate
(等誤り率) | FRRとFARが等しくなる点の誤り率 |
  • 値が小さいほど
    認証精度が高いシステムと評価される
|

| 用語 | 内容 | | --- | --- | | 本人認証の3要素 |
  • Something you know(知識)：パスワード等
  • Something you have(所持)：ICカード等
  • Something you are(生体)：指紋等
| | IdP / SP |
  • IdP(Identity Provider)：
    ユーザを認証し、認証結果を発行する主体
  • SP(Service Provider)：
    IdPの認証結果を受け取り
    サービスを提供する側
  • フェデレーション型SSO(SAML/OIDC等)で登場する用語
| | リプレイ攻撃 |
  • 過去に送信された認証情報を
    盗聴・再送して不正認証する攻撃
  • チャレンジレスポンス認証やOTPで対策可能
| | ゼロ知識証明 |
  • 秘密情報そのものを開示せずに
    その情報を知っていることを証明する方式
  • FIDO等の理論的背景の一つ
