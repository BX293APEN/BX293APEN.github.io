(XML Signature) | 署名規格
(W3C勧告) | XML文書(全体・一部の要素・外部リソース)に対するデジタル署名の標準規格

主な構成要素 :
  • <SignedInfo> : 署名対象の情報のまとまり(実際に署名される要素)
  • <Reference> :
    署名対象1件分の参照(URI、Transforms、DigestMethod、DigestValue)
    複数指定可
  • <SignatureValue> : <SignedInfo>に対する署名値
  • <KeyInfo> : 検証用の公開鍵・証明書(省略可)
  • <Object> : エンベロピング署名で対象データを格納する要素
|

  3. <SignedInfo>を正規化し、秘密鍵で署名して<SignatureValue>を生成する
  4. <KeyInfo>を付与し、<Signature>要素を形式に応じた位置に配置する
  5. 検証時はDigestValueの再計算と、SignatureValueの公開鍵による検証の両方を行う

TLS (Transport Layer Security) / SSL (Secure Sockets Layer)

TCP等の通信経路上でデータを暗号化し、盗聴・改ざん・なりすましを防ぐためのプロトコル
Netscape社が考案したSSLが起源で、後にIETFにより標準化され「TLS」と改称された
現行のSSLはすべて非推奨・廃止されており、実質的にTLSのみが利用されているが、慣習的に「SSL」「SSL/TLS」と併記されることも多い

提供する機能

  • 機密性 : 共通鍵暗号によるデータの暗号化
  • 完全性 : MAC(メッセージ認証符号)による改ざん検知
  • 認証 : デジタル証明書によるサーバ
    (および必要に応じクライアント)の身元確認

マルウェア感染発覚後の対応

  1. ネットワークから切り離す
    被害の拡大(他端末への感染拡大や外部への情報送信)を防ぐため、LANケーブルの抜線やWi-Fiの無効化により対象端末を直ちに隔離する
  2. マルウェアの駆除、変更されたシステムの修復
    アンチウイルスソフト等による駆除を行い、改ざんされたファイルや設定を正常な状態に復旧する
  3. PCの初期化、バックアップからの復元
    駆除・修復が困難な場合は、OSごと初期化した上で、感染前の健全なバックアップからデータを復元する
  4. マルウェア対策ソフトの更新、再度のマルウェア検索
    パターンファイル(シグネチャ)を最新の状態に更新した上で、再度全体をスキャンし、他の感染や残存がないかを確認する
  5. 問題の根本原因の調査、セキュリティ対策の改善
    感染経路や原因を分析し、再発防止のための対策(パッチ適用、教育、ルール見直し等)を講じる
