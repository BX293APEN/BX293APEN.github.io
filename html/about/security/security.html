| | シングルサインオン
(SSO) | 総称
(認証連携の仕組み) | **特徴**
  • 一度の認証(ログイン)で複数のサービス・システムを利用可能にする仕組み
  • 利用者はシステムごとにID/パスワードを覚える必要がなくなり
    利便性が向上する
  • パスワードの使い回しが減り、管理側でもアカウント管理・
    退職時のアクセス権限剥奪等を一元化できる
  • 実現方式(エージェント型、リバースプロキシ型、代理認証型、
    フェデレーション型)によって、必要なシステム改修や適用範囲、
    セキュリティ特性が異なる
  • SSO基盤自体が攻撃対象となった場合、複数システムへの
    侵入リスクが一度に高まる点に注意が必要
    (Kerberos認証も組織内SSOの実現方式の一つ)

**エージェント型**
  • 仕組み：各サーバ(アプリケーション)に常駐エージェントを導入し、
    SSO基盤と連携して認証を代行する
  • メリット：システムごとに柔軟な認証制御が可能
  • デメリット：対象サーバの台数分だけエージェントの導入・保守が
    必要でコストが増える
  • 必要なもの：各サーバへのエージェントインストール権限、
    SSO基盤との連携設定

**リバースプロキシ型**
  • 仕組み：SSO用リバースプロキシが全リクエストを中継し、
    認証済みセッションを各システムへ付与する
  • メリット：対象サーバ側の改修が不要(エージェント導入不要)で
    導入しやすい
  • デメリット：
    • 全通信が経由するため性能要件が高い
    • プロキシが単一障害点・ボトルネックになりやすい
  • 必要なもの：リバースプロキシサーバの構築、通信経路の集約

**代理認証型(フォーム認証代行)**
  • 仕組み：ユーザに代わってID/パスワードを各システムの
    ログイン画面へ自動入力し認証を代行する
  • メリット：既存システムの改修がほぼ不要で、
    レガシーシステムにも適用しやすい
  • デメリット：各システムのID/パスワードを別途保持・管理する
    必要があり、パスワード自体は残るため管理負荷や漏洩リスクがある
  • 必要なもの：各システムのログイン画面情報(フォーム構造)の登録、
    認証情報の保管(暗号化等)

**フェデレーション型(ID連携)**
  • 仕組み：IdP(Identity Provider)が認証を行い、
    認証結果をSP(Service Provider)へ連携する
  • メリット：組織・ドメインをまたいだ連携が可能で、
    SAML、OAuth 2.0、OpenID Connect等の標準規格で実現できる
  • デメリット：IdP・SP双方が規格に対応している必要があり、
    導入時の設定・信頼関係(トラストの確立)が必要
  • 必要なもの：IdPとSP間の標準プロトコル対応、
    証明書等による信頼関係の構築
| **エージェント型**
  1. 各サーバに常駐エージェントを導入する
  2. ユーザがアクセスするとエージェントがSSO基盤と連携し
    認証情報を確認する
  3. SSO基盤での認証結果をもとにエージェントが
    各サーバへの認証を代行する

**リバースプロキシ型**
  1. ユーザからのアクセスをSSO用リバースプロキシが中継する
  2. 未認証の場合はプロキシが認証を要求する
  3. 認証済みセッションを付与し各システムへリクエストを転送する

**代理認証型(フォーム認証代行)**
  1. ユーザがSSO基盤(代理認証エージェント等)に一度だけログインする
  2. 各システムのログイン画面が表示されると、
    登録済みのID/PWを自動入力する
  3. 各システム自身の認証処理により個別にログインを完了する

**フェデレーション型(ID連携)**
  1. IdP(Identity Provider)がユーザを認証する
  2. IdPが認証結果をSP(Service Provider)へ連携する
  3. SPが連携された認証結果を検証しログインを許可する
    (SAML、OAuth 2.0、OpenID Connect等で実現)

マルウェア感染発覚後の対応

  1. ネットワークから切り離す
    被害の拡大(他端末への感染拡大や外部への情報送信)を防ぐため、LANケーブルの抜線やWi-Fiの無効化により対象端末を直ちに隔離する
  2. マルウェアの駆除、変更されたシステムの修復
    アンチウイルスソフト等による駆除を行い、改ざんされたファイルや設定を正常な状態に復旧する
  3. PCの初期化、バックアップからの復元
    駆除・修復が困難な場合は、OSごと初期化した上で、感染前の健全なバックアップからデータを復元する
  4. マルウェア対策ソフトの更新、再度のマルウェア検索
    パターンファイル(シグネチャ)を最新の状態に更新した上で、再度全体をスキャンし、他の感染や残存がないかを確認する
  5. 問題の根本原因の調査、セキュリティ対策の改善
    感染経路や原因を分析し、再発防止のための対策(パッチ適用、教育、ルール見直し等)を講じる
