メールの認証・暗号方式

方式 正式名称 規格 手順 概要
暗号化・電子署名
S/MIME Secure/Multipurpose Internet Mail Extensions RFC 8551
  1. CAから証明書(X.509)を取得する
  2. 送信者が受信者の証明書の公開鍵で本文を暗号化する
  3. 送信者が自分の秘密鍵で電子署名を付ける
  4. 受信者が自分の秘密鍵で復号し、署名を検証する
  • X.509証明書でメール本文の暗号化と電子署名を行う
  • 認証局(CA)による階層型PKIで信頼を担保する
  • Outlook、Thunderbird、Apple Mail等で標準対応が多い
PGP Pretty Good Privacy OpenPGP
RFC 4880 / RFC 9580
  1. 利用者が自分で鍵ペアを生成する
  2. 公開鍵を相手と交換する
  3. 送信者が受信者の公開鍵で暗号化し、自分の秘密鍵で署名する
  4. 受信者が秘密鍵で復号し、署名を検証する
  • 公開鍵暗号によるメールの暗号化・署名方式
  • 代表的実装はGnuPG
  • 信頼モデルはWeb of Trust(相互署名による信頼の輪)
  • GnuPG連携やプラグインが必要な場合が多い
送信ドメイン認証
SPF Sender Policy Framework RFC 7208
  1. 送信側ドメインのDNSにTXTレコードで許可IPリストを登録する
  2. 受信側がメール受信時に送信元IPアドレスを確認する
  3. 送信ドメインのTXTレコードを参照して照合し、結果(pass/fail等)を判定する
  • 送信元IPアドレスが、DNS(TXTレコード)の許可リストに含まれるかを検証する
  • 送信ドメイン認証の一種
ARC Authenticated Received Chain RFC 8617
  1. 転送・中継を行う者が、受信時のSPF/DKIM認証結果を確認する
  2. 認証結果を記録し、中継者の署名を付与する
  3. 次の中継者・最終受信者が、署名のチェーンを検証する
  • メーリングリスト等の転送経由で崩れるSPF/DKIM認証結果を引き継ぐ
  • 中継者が署名付きで認証結果を保証する
通信路の暗号化
STARTTLS (正式名称なし。コマンド名) SMTP: RFC 3207
  1. 平文でSMTP/POP3/IMAPの接続を確立する
  2. クライアントが対応を確認し、STARTTLSコマンドを送る
  3. サーバーが了承し、TLSハンドシェイクを行う
  4. 以降の通信を暗号化して行う
  • 平文の接続をTLS接続へ昇格させるコマンド
  • SMTP・POP3・IMAPで利用される
POP3: RFC 2595(コマンド名はSTLS)
IMAP: RFC 2595 / RFC 9051
