| XMLデジタル署名<br>(XML Signature) | 署名規格<br>(W3C勧告) | XML文書(全体・一部の要素・外部リソース)に対するデジタル署名の標準規格<br>署名情報自体もXML(&lt;Signature&gt;要素)で表現される<br>形式の違いは「署名と署名対象の<b>位置関係</b>」で決まり、直下の3形式に分かれる<br>なお1つの&lt;Signature&gt;は複数の&lt;Reference&gt;を持てるため、<br>1対1・1対多といった数の関係は形式ではなく&lt;Reference&gt;の数で決まる<br>XMLは意味が同じでも空白・属性順等の表記が変わりうるため、<br>署名・検証の前に「正規化(C14N : Canonicalization)」を行う<br>主な構成要素 : <ul><li>&lt;SignedInfo&gt; : 署名対象の情報のまとまり(実際に署名される要素)</li><li>&lt;Reference&gt; : <br>署名対象1件分の参照(URI、Transforms、DigestMethod、DigestValue)<br>複数指定可</li><li>&lt;SignatureValue&gt; : &lt;SignedInfo&gt;に対する署名値</li><li>&lt;KeyInfo&gt; : 検証用の公開鍵・証明書(省略可)</li><li>&lt;Object&gt; : エンベロピング署名で対象データを格納する要素</li></ul> | <ol><li>署名対象を&lt;Reference&gt;のURIで指定する</li><li>対象に変換(Transform : 正規化等)を適用し、ダイジェストを計算して&lt;DigestValue&gt;に格納する</li><li>&lt;SignedInfo&gt;を正規化し、秘密鍵で署名して&lt;SignatureValue&gt;を生成する</li><li>&lt;KeyInfo&gt;を付与し、&lt;Signature&gt;要素を形式に応じた位置に配置する</li><li>検証時はDigestValueの再計算と、SignatureValueの公開鍵による検証の両方を行う</li></ol> | <ul><li>デジタル署名・証跡</li><li>SOAPメッセージ(WS-Security)</li><li>電子申請システム等</li><li>XAdES(XML署名にタイムスタンプ等を加えた長期署名の拡張規格)</li><li>XML Encryption(XMLの暗号化規格)とは別規格</li></ul> |
| &emsp;└ エンベローピド署名<br>(Enveloped Signature) | XML署名の形式 | <ul><li>署名が、対象に<b>包まれる</b>(対象の内側に署名を書く)</li></ul><br><b>対象</b><ul><li>署名を含む文書全体(URI="")</li><li>署名を含む特定の親要素(URI="#id")</li></ul><br><b>署名関係</b><ul><li><b>基本</b><br>1署名 : 1文書(1対1)</li><li><b>署名者が複数</b><br>署名を追加して多対1も可能<br>(他の署名を対象に含めるかの設計が必要)</li></ul><br><b>署名場所</b><ul><li><b>対象の内部</b>に書く<br>(「属する文書」が対象)</li><li>署名自身が対象に含まれてしまうため、<br>署名要素を対象から除外する変換(enveloped-signature)が必須</li></ul><br><b>構造イメージ</b><br><code>Invoice&emsp;←署名対象<br>&nbsp;├ Amount<br>&nbsp;└ Signature&emsp;←対象の内側</code> | <ol><li>署名対象(通常は文書全体 : URI="")を&lt;Reference&gt;で指定する</li><li>Transformsに「enveloped-signature変換」と正規化を指定する</li><li>ダイジェストを計算し、&lt;SignedInfo&gt;に署名する</li><li>&lt;Signature&gt;要素を対象文書の内部に挿入する</li></ol> | <ul><li>1ファイルで署名と文書を完結させたい場合</li><li>SAMLアサーション・レスポンスの署名</li><li>電子申請の署名付きXML文書</li></ul> |
| &emsp;└ エンベロピング署名<br>(Enveloping Signature) | XML署名の形式 | <ul><li>署名が、対象を<b>包む</b>(署名の内側に対象を書く)</li></ul><br><b>対象</b><ul><li>&lt;Signature&gt;内の&lt;Object&gt;要素に格納したデータ</li><li>XML以外のデータ(Base64化したバイナリ等)も対象にできる</li></ul><br><b>署名関係</b><ul><li>1署名 : 1つ以上の&lt;Object&gt;</li><li>Objectを複数入れれば1署名で複数データを署名(1対多)</li></ul><br><b>署名場所</b><ul><li><b>署名が親、対象が子</b>(対象は署名の内部に書く)</li><li>&lt;Reference&gt;でURI="#id"により内側のObjectを参照</li><li>元データを使うには署名要素から取り出す</li></ul><br><b>構造イメージ</b><br><code>Signature&emsp;←署名が外側<br>&nbsp;└ Object&emsp;←対象が内側<br>&nbsp;&nbsp;&nbsp;└ 対象データ</code> | <ol><li>署名対象データを&lt;Signature&gt;内の&lt;Object&gt;要素に格納する</li><li>&lt;Reference&gt;でそのObject要素をID参照(URI="#id")する</li><li>ダイジェストを計算し、&lt;SignedInfo&gt;に署名する</li></ol> | <ul><li>バイナリや任意データを1つのXMLにまとめて署名する用途</li></ul> |
| &emsp;└ デタッチ署名<br>(Detached Signature) | XML署名の形式 | <ul><li>署名と対象が、互いに包まず<b>別々</b>(署名は対象を参照するだけ)</li></ul><br><b>対象</b><ul><li>同一XML文書内の特定要素(URI="#id")</li><li>外部ファイル(URI="https://…")</li><li>混在(文書の一部だけを対象にできる)</li></ul><br><b>署名関係</b><ul><li>1署名で複数の要素・リソースをまとめて署名(1対多)</li><li>複数署名者が同じ対象に署名(多対1)</li><li>多対多</li><li>3形式中最も柔軟</li></ul><br><b>署名場所</b><ul><li><b>対象の外側</b>に書き、対象を参照する</li><li>同一文書内の別要素への署名なら、<b>同じXML文書に含める</b>ことも可能(対象の兄弟要素などに配置)</li><li>対象を改変せずに署名できるが、署名と対象が分離すると検証できない</li></ul><br><b>構造イメージ</b><br><code>Order&emsp;←署名対象①(id=o1)<br>Item&emsp;←署名対象②(id=i1)<br>Signature&emsp;←対象の外側から参照<br>&nbsp;├ Reference URI="#o1"<br>&nbsp;└ Reference URI="#i1"</code> | <ol><li>署名対象の要素・リソースを&lt;Reference&gt;のURI(#idまたは外部URI)で指定する</li><li>ダイジェストを計算し、&lt;SignedInfo&gt;に署名する</li><li>&lt;Signature&gt;要素を対象の外側(別ファイル、または同一文書内の別の位置)に配置する</li></ol> | <ul><li>文書の一部の要素だけに署名する用途</li><li>SOAPメッセージのヘッダ・ボディ等の個別要素の署名(WS-Security)</li><li>注意 : ID参照方式では、署名済み要素を別の位置へ移して偽要素を差し込む<br>XML Signature Wrapping攻撃に備え、署名された要素そのものを処理に使うこと</li></ul> |
