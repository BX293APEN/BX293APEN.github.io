情報セキュリティについて

セキュリティ

  • 安全
  • 守らなければならない大切なモノが危害や損害を受けない正常な状態

情報セキュリティ

以下の項目を維持すること

項目 内容
機密性 [C] アクセス権限
完全性 [I] 情報が正確・改竄されていない
可用性 [A] 必要な時使える
真正性 利用者・プロセス・システム・情報が本物であると証明
責任追跡性 ログの記録
否認防止 事後に「やっていない」と言えなくする (タイムスタンプ, 電子署名等)
信頼性 意図した通りに矛盾なく動作

不正の発生原因

動機

  • 金銭奪取
  • ハクティビズム (政治的・社会的思想)
  • サイバーテロリズム

サイバーキルチェーン (攻撃の手順)

段階 内容
1. 偵察 インターネットなどから組織や人物を調査し、対象組織に関する情報を取得する
2. 武器化 エクスプロイトやマルウェアを作成する
3. デリバリ なりすましメール (マルウェアを添付) を送付する
なりすましメール (マルウェア設置サイトに誘導) を送付し、ユーザにクリックするように誘導する
4. エクスプロイト ユーザにマルウェア添付ファイルを実行させる
ユーザをマルウェア設置サイトに誘導し、脆弱性を使用したエクスプロイトコードを実行させる
5. インストール エクスプロイトの成功により、標的がマルウェアに感染する
6. C&C マルウェアとC&Cサーバを通信させて、感染PC を遠隔操作する
新たなマルウェアやツールのダウンロード等により、感染拡大や内部情報の探索を試みる
7. 目的の実行 探し出した内部情報を、加工 (圧縮や暗号化等) した後、情報を持ち出す
高度サイバー攻撃への対処におけるログの活用と分析方法 より

サイバー攻撃

攻撃者の種類

| 種類 | 説明 | |---|---| | クラッカー | コンピュータやネットワークに不正侵入し、破壊・改ざん・情報窃取等の悪意ある行為を行う者
「ハッカー」は本来、高度な技術を持つ者を指す中立的な語であり、悪意ある行為者は「クラッカー」と呼ぶのが技術的には正しい(ただし一般には「ハッカー」が悪意ある意味でも使われる) | | スクリプトキディ | 自らは高度な技術を持たず、他者が作成した攻撃ツールやスクリプトを利用して攻撃を行う初心者的な攻撃者 | | ハクティビスト | 政治的・社会的な主張を目的として、Webサイト改ざんやDDoS攻撃等を行う攻撃者 | | ボットハーダー | マルウェアに感染させた多数の端末(ボット)からなるボットネットを構築・遠隔操作する攻撃者 | | 内部関係者(インサイダー) | 従業員・元従業員・委託先担当者等、正規のアクセス権を持つ立場を悪用して情報漏えいや破壊行為を行う者。金銭目的、恨み、過失など動機は様々 | | 犯罪組織(サイバー犯罪集団) | 金銭的利益を目的として組織的にランサムウェア配布、フィッシング、不正送金等を行う集団。RaaS(Ransomware as a Service)のように攻撃基盤自体を商品化する例もある | | 詐欺犯 | フィッシングやビジネスメール詐欺(BEC)など、心理的な誘導によって金銭や情報をだまし取ることを目的とする者 | | APT攻撃者(標的型攻撃者) | 特定の組織を標的に、長期間・持続的に潜伏しながら情報窃取や妨害を行う高度な攻撃者。国家関与主体が背後にいる場合が多い | | 国家関与主体(ネーションステートアクター) | 国家の支援・関与を受け、諜報活動・重要インフラ攻撃・サイバー戦を目的として活動する攻撃者。高度な技術力と資金力を持つ | | 産業スパイ | 競合企業の技術情報・営業情報等を不正に取得することを目的とする者 | | 内部告発者との違いに注意すべき者(悪意ある退職者等) | 解雇・処遇への不満等を動機に、退職前後に情報持ち出しやシステム破壊を行う者 |

Nmap 等が代表例 | | ファジング | 想定外の値・不正な形式のデータ(ファズ)を大量に入力し、ソフトウェアの異常終了や未知の脆弱性を検出する手法 | | 脆弱性診断(脆弱性スキャナ) | 既知の脆弱性データベース(CVE 等)と照合し、対象システムに既知の脆弱性が存在しないかを網羅的に確認する検査 | | ソースコード診断(静的解析 / SAST) | プログラムを実行せずソースコードを解析し、脆弱性の原因となるコーディング上の欠陥を検出する手法 | | Webアプリケーション診断(動的解析/ DAST) | 実際にアプリケーションを動作させ、外部からリクエストを送って脆弱性(SQLインジェクション、XSS 等)を検出する手法 | | 構成管理監査(コンフィグレーションチェック) | OS・ミドルウェアの設定値がセキュリティ基準(ベースライン)に適合しているかを確認する検査 |

障害対策の手法

Fault : 故障・障害 (障害発生前に準備)

名前 読み方 種別 内容
Fault Tolerant フォールト トレラント 手法 障害発生時、機能を縮小せずに継続させる
多重化
Fault Avoidance フォールト アボイダンス 手法 事前対策により、障害を回避する
高級な部品にする等...
Fault Masking フォールト マスキング 考え方 障害の影響を他に与えないようにする

Fool : 愚かな (人間の過ち)

名前 読み方 種別 内容
Fool Proof フール プルーフ 考え方 ユーザが誤操作しても安全に稼働させる

Fail : 失敗する (障害発生後の処理)

名前 読み方 種別 内容
Fail Safe フェイル セーフ 考え方 機械が異常・故障の際に安全側に作動する
Fail Soft フェイル ソフト 考え方 障害発生時、機能を縮小してでも稼働継続を優先する
Fail Over フェイル オーバー 機能 障害発生時、自動的に予備システムに切り替える
↳ Fail Back フェイル バック 機能 フェイル オーバー(Fail Over)した予備から再度本来の構成に戻すこと

Fall : 落とす

名前 読み方 種別 内容
Fall Back フォール バック 機能 障害発生時、機能や性能を落として稼働させること
異常個所を切り離し、予備の機材を使用すること等
縮退運転
