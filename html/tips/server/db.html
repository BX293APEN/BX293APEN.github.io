データベースサーバ

データ基盤の分類

分類 特徴 種類 特徴 サブ分類 説明 具体例
DB
  • 最新の状態
  • データを構造化して保存・管理し、検索や更新を効率的に行う
  • 業務システムの日々の読み書き(OLTP)に適する
  • 常に最新の状態のデータを保持
  • アプリケーションから直接利用される
 RDBMS
  • 表(テーブル)形式でデータを管理
  • スキーマを事前に定義
  • ACID特性によるトランザクション保証
  • SQLによる問い合わせ・結合が可能
 (リレーショナル型)
  • 行と列からなる表でデータを表現
  • 外部キーによりテーブル同士を関連付け
  • 整合性・正確性が求められる業務系システムに適する
  • MySQL
  • PostgreSQL
  • SQLite
  • Oracle Database
  • SQL Server
NoSQL
  • スキーマレス(柔軟なデータ構造)
  • 水平分散によるスケールアウトが容易
  • 大量データ・高速アクセスに強い
  • 結合(JOIN)には不向き
 KVS型
  • キーと値のペアでデータを保持
  • 構造がシンプルで読み書きが非常に高速
  • キャッシュやセッション管理に多用
  • Redis
  • Memcached
  • Amazon DynamoDB
ドキュメント型
  • JSON/BSON等の半構造化ドキュメント単位で保存
  • ドキュメントごとに異なる構造を持てる
  • アプリケーションのオブジェクトと親和性が高い
  • MongoDB
  • Couchbase
  • Amazon DocumentDB
カラムファミリ型
  • 行ごとに異なるカラムを持てる列指向のデータ構造
  • 大規模・書き込み中心のワークロードに強い
  • ノード追加による水平スケールが得意
  • Apache Cassandra
  • HBase
  • ScyllaDB
グラフ型
  • ノードとエッジでデータ間の関係を表現
  • 関係性をたどる探索クエリが高速
  • SNSの人間関係やレコメンドに適する
  • Neo4j
  • Amazon Neptune
  • ArangoDB
データレイク
  • 加工前の生データ
  • 生データをそのままの形式で大量に蓄積
  • 構造化・半構造化・非構造化データを区別なく保存
  • 読み込み時にスキーマを適用(Schema on Read)
  • 機械学習や探索的分析のデータソースに適する
 オブジェクトストレージ型
  • 低コストで容量をほぼ無制限に拡張可能
  • ストレージと計算資源を分離して個別にスケール可能
  • HTTP APIでファイル(オブジェクト)単位にアクセス
 (クラウドストレージ型)
  • ログ、画像、動画、CSV、JSONなどをファイル単位で保存
  • クラウド上のデータレイクの基盤として最も一般的
  • 各種分析サービスから直接読み込める
  • Amazon S3
  • Azure Data Lake Storage
  • Google Cloud Storage
分散ファイルシステム型
  • 複数ノードにファイルを分割・複製して保存
  • ノード追加による水平スケールが容易
  • データの近くで処理を実行できる(データローカリティ)
 (オンプレミス型)
  • Hadoopエコシステムを中心に発展したデータレイクの原型
  • 自社環境で大規模データを扱う場合に利用
  • MapReduceやSparkによる大規模バッチ処理に適する
  • HDFS
  • Apache Ozone
  • GlusterFS
レイクハウス型
  • データレイク上にテーブル形式の管理層を追加
  • ACIDトランザクションやスキーマ管理に対応
  • 1つの基盤でBIと機械学習の両方を扱える
 (テーブルフォーマット型)
  • データレイクの柔軟性とDWHの信頼性を両立
  • タイムトラベル(過去時点のデータ参照)などに対応
  • Parquet等のファイルに対してメタデータ層を提供
  • Delta Lake
  • Apache Iceberg
  • Apache Hudi
データウェアハウス
  • 加工・統合済みのデータ
  • 複数システムのデータを統合・整形して蓄積
  • 分析・レポート用途(OLAP)に最適化
  • 書き込み時にスキーマを定義(Schema on Write)
  • BIツールと連携した経営分析・意思決定に適する
 クラウドDWH
  • 列指向ストレージによる高速な集計・分析
  • インフラ管理が不要なマネージドサービス
  • 需要に応じて柔軟にスケール可能
 (マネージドサービス型)
  • ストレージと計算資源を分離できる製品が多い
  • SQLで大量データを扱えるため、アナリストが使いやすい
  • 従量課金で小さく始められる
  • Google BigQuery
  • Amazon Redshift
  • Snowflake
  • Azure Synapse Analytics
オンプレミスDWH
  • 自社データセンター内にDWHを構築・運用
  • 並列処理による大規模な集計に対応
  • データの所在やセキュリティを自社で管理できる
 (アプライアンス型)
  • 専用のハードウェアとソフトウェアを組み合わせた製品が中心
  • 規制やセキュリティ要件でクラウドを使えない場合に選択
  • 導入・拡張には初期投資と運用負荷が必要
  • Teradata
  • Oracle Exadata
  • IBM Db2 Warehouse
