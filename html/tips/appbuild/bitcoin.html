ビットコインの仕組み

ビットコイン

  • ビットコインのブロックチェーンは分散型台帳
  • 今までの取引内容がすべて書かれた台帳で、世界中のノードが同じ写しを持つ
  • 取引(トランザクション)は電子署名で「持ち主本人が出した」ことを証明する
  • 取引はブロックにまとめられ、各ブロックは直前のブロックのハッシュ値を持って鎖状につながる
  • ブロックの追加はProof of Work(ハッシュ計算の競争)で決まり、特定の管理者(第三者)を必要としない
  • ブロックにはタイムスタンプがあり、取引がいつ確定したかの目安になる
  • 過去のブロックを改ざんするとハッシュ値が変わり、以降のブロックとの整合性が崩れる

難易度が上がるほど 0 の数が増える | | `xxx...xxx` | 任意の値 (`x` は 0〜f の任意の16進数字)

トランザクションの中身

| 要素 | 内容 | |---|---| | txid |
  • TXをシリアライズして SHA-256 を2回適用したハッシュ値
  • TXの識別子として使う
  • SegWit のTXでは witness を除いて計算する (witness を含めたものは wtxid)
| | UTXO (Unspent Transaction Output) |
  • まだ使われていない出力
  • ビットコインの「残高」の実体
  • 所持金は、自分が解除できる UTXO の合計になる
| | ロック条件 (`scriptPubKey`) |
  • 出力に付ける「このお金を使うには何が必要か」の条件
  • 通常は「この公開鍵ハッシュに対応する鍵の署名」を要求する
  • 鍵付きの箱に入れることに当たる
| | 解除条件 `witness` |
  • 過去の出力のロックを解くために、入力側に添える証拠
  • **SegWit 形式 (P2WPKH、P2WSH、P2TR)**
  • TXの末尾に入力ごとに置く
  • P2WPKH では署名と公開鍵、P2TR のキーパスでは Schnorr署名
  • txid の計算に含まれない (wtxid には含まれる)
  • ブロック容量には 1/4 として数える
| | 解除条件 `scriptSig`
互換性維持 |
  • 過去の出力のロックを解くために、入力側に添える証拠
  • **レガシー形式 (P2PKH、P2SH)**
  • 入力の中に置く
  • 通常は署名と公開鍵
  • txid の計算に含まれる
  • 箱を開ける鍵を差し出すことに当たる
| | 入力 (input) |
  • 消費する過去の出力 (`prev_txid`, `vout`)
  • それを解除する解除条件 (`scriptSig` / witness)
| | 出力 (output) |
  • 金額 (satoshi)
  • 受取人のロック条件 (`scriptPubKey`)
  • 使われるまでは UTXO になる
| | 送金主 |
  • 消費する UTXO の持ち主
  • 秘密鍵で署名してロックを解除する
| | 受取人 |
  • 出力のロック条件に指定された公開鍵ハッシュの持ち主
  • 次に使うときに、自分の秘密鍵で解除する
| | マイナー |
  • TXをブロックにまとめる人
  • 手数料を、ブロックのコインベースTXで受け取る
| | お釣り |
  • 使い切れなかった分を、送金主自身のアドレスへ戻す出力
  • UTXO は分割できないため必要
| | locktime |
  • TXが有効になる時刻またはブロック高の制限
| | 手数料 |
  • 入力の合計 - 出力の合計
  • マイナーが受け取る
|
